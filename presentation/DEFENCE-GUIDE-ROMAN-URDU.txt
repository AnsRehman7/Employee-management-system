--------------------------------------------------------------------------------
8.1 - MODEL KYA KARTA HAI
--------------------------------------------------------------------------------

Model ka kaam: "Task ka title aur description parh kar batana ke ye task
kitna bara hai (kitni mehnat lagegi)."

Misaal:
  "Fix typo in README"                              -> 1.0  (bohat chhota kaam)
  "Update documentation for the API"                -> 3.1  (darmiyana)
  "Implement distributed transaction coordinator"   -> 8.3  (bohat bara kaam)

Phir in numbers se hum har task ka WEIGHT nikalte hain (percentage), aur
sab weights milkar 100% bante hain.

FAIDA KYA HAI:
Pehle: 4 tasks the, har task complete karne par 25% progress barhti thi
       (chahe wo task chhota ho ya bara - ye ghalat hai)

Ab:    Bara task complete karo to zyada progress barhti hai
       Chhota task complete karo to kam progress barhti hai

--------------------------------------------------------------------------------
8.2 - DATA KAHAN SE LIYA (ye zaroor yaad rakho)
--------------------------------------------------------------------------------

Data ka naam:  Story Point Dataset
Kitna data:    23,313 real tasks
Kahan se:      16 open-source projects (Apache Mesos, Moodle, Talend,
               Appcelerator, Spring XD waghera)
Kis ne banaya: Ye dataset ek research paper ke saath aaya tha:

  "A Deep Learning Model for Estimating Story Points"
  Choetkiertikul et al., IEEE Transactions on Software Engineering, 2019
  (Ye hamara BASE PAPER hai)

SAB SE ZAROORI BAAT:
Is data mein har task ke saath uska "story point" likha hai - matlab asal
engineering team ne khud batayi thi ke ye task kitna bara hai.
To hamare paas SAHI JAWAB pehle se maujood tha - isi liye model train ho saka.

AGAR TEACHER POOCHE "khud data kyun nahi banaya?":

8.3 - TRAINING KAHAN KI
--------------------------------------------------------------------------------

KAGGLE par (kaggle.com) - ye Google ki free website hai jahan Python code

  - Laptop slow tha (8 GB RAM, koi graphics card nahi)
  - Kaggle free hai aur tez hai

Total training time: 2 minute 55 second

--------------------------------------------------------------------------------
8.4 - TRAINING KE STEPS (5 STEPS - YE YAAD KARO)
--------------------------------------------------------------------------------

STEP 1: DATA LOAD KIYA
  16 files download kar ke jorin -> 23,313 tasks

STEP 2: DATA SAAF KIYA (Preprocessing)
  - Sab text ko lowercase kiya
  - Punctuation aur symbols hataye
  - Kharab rows nikal di
  - 701 rows nikalni pari
  - Bache: 22,612 tasks

STEP 3: TEXT KO NUMBERS MEIN BADLA (TF-IDF)
  Computer text nahi samajhta, sirf numbers samajhta hai.
  TF-IDF ek tareeqa hai jo har lafz ko number deta hai.

  ASAAN MISAAL:
  Agar "database" lafz kam tasks mein aata hai lekin is task mein hai,
  to wo lafz zyada important hai. Agar "the" har jagah hai to wo
  important nahi.

  Humne 4,000 sab se important lafz chune (single words + do lafz ke jore)

STEP 4: DATA KO DO HISSON MEIN BANTA
  - Training: 18,089 tasks (80%)  -> model isse SEEKHTA hai
  - Testing:  4,523 tasks  (20%)  -> model ne ye KABHI NAHI DEKHE

  YE BOHAT ZAROORI HAI. Agar hum usi data par test karte jisse seekha tha,
  to result jhoota hota - jaise imtihan mein wahi sawal aayen jo yaad karwaye the.

STEP 5: MODEL TRAIN KIYA
  Teen models banaye aur compare kiye:
    a) Baseline    - sirf average number bolta hai (bewakoof model)
    b) Ridge Regression + TF-IDF
    c) Random Forest

--------------------------------------------------------------------------------
8.5 - RESULTS (YE NUMBERS ZUBANI YAAD KARO)
--------------------------------------------------------------------------------

  Model                    MAE      RMSE     R2        Within +/-1
  ---------------------------------------------------------------
  Baseline (bewakoof)      2.880    3.955    0.000     23.3%
  Random Forest            2.665    3.657    +0.144    24.2%
  Ridge + TF-IDF  <--      2.587    3.575    +0.182    27.9%   (HUMNE YE LAGAYA)

  5-fold Cross Validation: 2.713 (+/- 0.038)

IN NUMBERS KA MATLAB (asaan alfaaz mein):

MAE (Mean Absolute Error) = "aausatan kitni ghalti"
  Baseline ki ghalti: 2.880
  Hamare model ki ghalti: 2.587
  Matlab hamara model 10.2% behtar hai

R2 (R-squared) = "model kitna samajhta hai"
  0.000 matlab bilkul nahi samajhta (baseline aisa hi hai)
  0.182 matlab hamara model 18% cheezein samajh leta hai

WITHIN +/-1 = "kitni baar jawab 1 point ke andar sahi tha"
  Baseline: 23.3%
  Hamara: 27.9%

CROSS VALIDATION (+/- 0.038) = "result qismat ka nahi hai"
  Humne training 5 baar alag alag data se ki, har baar wahi result aaya.
  Chhota +/- matlab result reliable hai.

--------------------------------------------------------------------------------
8.6 - BASELINE KYA HAI (YE SAWAL ZAROOR AAYEGA)
--------------------------------------------------------------------------------

Baseline ek "bewakoof model" hai jo kuch nahi seekhta - bas har baar wahi
average number bol deta hai (6.2).

Hum isse kyun banate hain?
Taake pata chale ke hamara model waqai kuch seekha hai ya nahi.

Agar hamara model baseline se behtar nahi hota, to matlab usne kuch nahi
seekha - bas number guess kar raha hai.

Hamara model baseline se 10.2% behtar hai -> matlab usne WAQAI SEEKHA HAI.

Aur dekho: Baseline ka R2 = 0.000 hai (kuch nahi samajhta)
           Hamara R2 = 0.182 hai (kuch samajhta hai)

--------------------------------------------------------------------------------
8.7 - MODEL APP MEIN KAISE LAGAYA (ye technically achi baat hai)
--------------------------------------------------------------------------------

MASLA: Model Python mein bana tha, lekin hamara backend Node.js (JavaScript) hai.

AAM HAL: Ek alag Python server banao aur usse baat karo
         Lekin isme: extra server, extra kharcha, extra cheez jo kharab ho sakti hai

HAMARA HAL:
  Ridge regression asal mein sirf zarb aur jama hai (simple maths).
  To humne model ki "seekhi hui cheezein" ek JSON file mein save kar li
  (230 KB ki chhoti file), aur wahi maths JavaScript mein likh di.

FAIDA:
  - Koi alag server nahi chahiye
  - Bilkul free
  - Internet ki zaroorat nahi prediction ke liye
  - Demo mein fail hone ka chance zero

AGAR TEACHER POOCHE "kya ye cheating hai?":

tak hai. Hamara 2.587 usi range mein hai. Aur zaroori baat ye hai ke hum
baseline se behtar hain aur cross-validation se sabit hai ke result stable hai."
